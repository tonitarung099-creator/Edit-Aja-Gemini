READ FIRST, WRITE SECOND

4. Periksa perubahan terbaru yang relevan.

7. Jika gagal, lihat status seluruh job dan seluruh step.

10. Bedakan warning, error non-fatal, secondary error, dan root cause.

12. Periksa API/dependency/upstream jika diperlukan.
13. Tentukan owning failure domain.
14. Tentukan blast radius perubahan.

FULL-LOG RULE

Jika sebuah workflow gagal:

- Jangan berhenti membaca hanya karena menemukan kata "error".
- Periksa apakah step tempat teks tersebut muncul benar-benar FAIL.
- Periksa apakah command tersebut memang menghasilkan exit code gagal.
- Cari step pertama yang benar-benar menyebabkan job gagal.
- Baca konteks log sebelum dan sesudah error.
- Bedakan error diagnostik sementara dari error terminal.

Contoh:
Jika "Windows Compile" berstatus SUCCESS dan "Packaging" berstatus FAIL,
maka dilarang menyebut masalah tersebut sebagai compile failure.

Aturan penting:

- CODE CHANGED bukan PASS.
- Static test PASS bukan berarti compile PASS.
- Compile PASS bukan berarti packaging PASS.
- Packaging PASS bukan berarti artifact benar.
- Artifact tersedia bukan berarti aplikasi bisa dijalankan.
- Smoke test belum dilakukan berarti aplikasi belum boleh disebut siap.
- PASS pada satu tahap tidak otomatis membuat tahap berikutnya PASS.

EVIDENCE LADDER

TINGKAT 0 — HIPOTESIS
Masih dugaan. Jangan disebut berhasil.

TINGKAT 1 — KODE BERUBAH
Implementasi sudah dibuat. Belum membuktikan perilaku benar.

TINGKAT 2 — STATIC / UNIT PASS
Logic dasar atau struktur terverifikasi sebagian.

TINGKAT 3 — COMPONENT / INTEGRATION PASS
Hubungan komponen relevan telah diuji.

TINGKAT 4 — SOURCE RECONSTRUCTION PASS
Source upstream + patch chain berhasil dibangun kembali dengan benar.

TINGKAT 5 — WINDOWS COMPILE PASS
Compiler Windows benar-benar menerima source.

TINGKAT 6 — PACKAGING PASS
Package/installer benar-benar dibuat.

TINGKAT 7 — ARTIFACT VERIFIED
Artifact ditemukan, ukuran masuk akal, dan berasal dari build yang benar.

TINGKAT 8 — SMOKE TEST PASS
Packaged app benar-benar dapat dijalankan dan alur utama dasar berfungsi.

TINGKAT 9 — RELEASE VERIFICATION PASS
Baru boleh disebut release-ready.

BUILD LOOP PROTECTION

Jika build gagal:

1. Jangan langsung membuat patch baru.
2. Periksa workflow/job/step aktual.
3. Baca log aktual.
4. Temukan root cause.
5. Buat test atau preflight reproduction jika memungkinkan.
6. Perbaiki akar masalah.
7. Jalankan test murah terlebih dahulu.
8. Review diff.
9. Baru jalankan build ulang.

Jika fix sebelumnya gagal:

- Jangan membuat fix kedua berdasarkan asumsi fix pertama.
- Baca hasil build baru dari awal.
- Pastikan failure domain benar.
- Jika kegagalan berulang pada area yang sama, hentikan patch loop.
- Audit subsystem tersebut secara lebih luas.

Jangan melakukan random trial-and-error.

DEFINITION OF DONE

Jangan menyebut pekerjaan "selesai" hanya karena:
- kode ditulis;
- patch diterapkan;
- test lokal PASS;
- workflow hijau;
- compile selesai;
- package dibuat.

Definition of done bergantung pada jenis pekerjaan.

Untuk release-ready minimal diperlukan bukti:
- source dapat direkonstruksi;
- Quality Gates penting PASS;
- dependency berhasil;
- Windows compile PASS;
- packaging PASS;
- artifact tersedia;
- packaged application dapat dijalankan;
- project sederhana dapat dibuka;
- operasi edit penting dapat dilakukan;
- render/export sederhana berhasil.

Jika ada yang belum diuji, gunakan NOT TESTED.

SMOKE TEST

Packaging dan smoke test adalah dua hal berbeda.

Smoke test packaged application minimal memeriksa hal-hal yang relevan seperti:
- executable dapat start;
- tidak langsung crash;
- UI utama tampil;
- project baru dapat dibuat/dibuka;
- media dapat dimuat;
- timeline dasar bekerja;
- fitur penting yang baru diubah tersedia;
- render/export sederhana dapat dilakukan;
- output dasar dapat dibuka.

Jangan menyebut aplikasi siap hanya karena installer berhasil dibuat.
